# Living memory

## Product

- **Signal2Speech** is a hands-free communication prototype. AI Answering suggests replies to a question. The EEG wearer selects, previews, and confirms the exact words before the app speaks.
- **OpenOrbit** uses the same controls to explore NASA imagery and EPA air quality. Its MVP is one confirmed map-and-speech reveal. From June 26 to June 28, 2023, Washtenaw AQI rose from 32 to 218 and Wayne AQI from 58 to 226.

## Decisions and open questions

- **Stack (pivoted 2026-11-14):** Python 3.12, g.Pype 4.2, and PySide6 in one process. We use the Unicorn Hybrid Black through the `HybridBlack` source with OSCAR on. No Unity, no Unicorn Suite, and no licence needed. Use keyboard or `Generator` input before live headset access.
- Use platform APIs and hardware-required packages. Bundle OpenOrbit data and demo audio locally.
- Selection contract is final in [#22](https://github.com/Order-of-the-Golden-Eagles/Signal2Speech/issues/22). It covers the event shape, IDs, round rules, folder ownership, and dependency order. See [selection-contract.md](architecture/selection-contract.md). `signal2speech/core/` holds the pure-Python handler, and `pytest` must stay green. Live EEG confirm stays disarmed until #23.
- **Decoding:** choose with P300 (our flashing tiles → `Epochs` → `Sklearn` LDA, #46). Confirm with an alpha switch, eyes closed for about 2 s (#47). Fallback: step through options one at a time and confirm each with the alpha switch. Judges see evidence scopes (#48). The #46 chooser and #48 view are merged and verified on synthetic data only. The chooser is not yet wired into `app.py`.
- **Simulated input works (#21):** `python -m signal2speech.eeg.simulated --picks 2,1` runs a real g.Pype `Generator` pipeline into the handler, labelled `simulated`. #24 and #25 can rehearse against it. `python -m signal2speech.app --input simulated` uses it automatically (#60), and falls back to labelled scripted input only if it fails to import. Verified on Linux with Python 3.12 and g.Pype 4.2.0. [Details](eeg-hardware/README.md#simulated-input-21--works)
- **Qt app rule:** create the app with `QApplication`, never `QCoreApplication`. The first one created wins, and the #24 widgets crash pytest otherwise. In a `main()` that tests call in-process, never leave a `QTimer.singleShot` guard pending: own the timer and `stop()` it on return. Otherwise it fires in a later test's event loop. #26 found this when `app.py --screenshot`'s 30 s guard exited another test's loop with code 1.
- **Ask the g.tec mentor:** Paradigm Presenter licence, MCP visualizer access, and whether one headset can stream to two apps at once.
- **AI provider (#5):** the code defaults to Claude (`claude-sonnet-5-5`) when `ANTHROPIC_API_KEY` is in `.env`. Otherwise it uses a labelled Stub, and it falls back to saved phrases on a timeout or error. Replies are grounded in a "Verified facts" block built from the OpenOrbit data, and Claude can suggest the compare or satellite map action, whose spoken line always comes from the dataset (#106). Live calls verified on 2026-11-14, including one in the AI demo window: a real reply in about 2 s, previewed, confirmed, and spoken once. Before the grounding, it answered the AQI question wrongly ("Wayne"). See the [architecture walkthrough and input contract](architecture/README.md) and [AI Answering](ai-answering/README.md).

- **Check your clone if you pushed with the hooks on (fixed by the `test_githooks` env fix):** git exports `GIT_DIR` to hooks, so `tests/test_githooks.py` ran its git commands against your *real* repo during the pre-push pytest. Run `git config --local --list`. If you see `core.bare=true`, `user.name=Hook Test`, `user.email=test@example.com`, `commit.gpgsign=false`, or an absolute `core.hookspath`, fix them:
  1. `git --git-dir=.git config --local core.bare false`
  2. `git config --local core.hooksPath .githooks`
  3. If present: `git config --local --unset commit.gpgsign`
  4. If present: `git config --local --unset user.name` and `git config --local --unset user.email` (or set your own)

  Then check the index and history:
  - Run `git status`. The tests may have left `leak.py` (a fake secret), `.env`, or `.env.example` staged. They also ran `git reset` on your real index, so anything you had staged may be unstaged. Remove the stray files with `git rm --cached <file>` and delete them, then re-stage your own work.
  - Run `git log --all --author='Hook Test'` for stray commits ("add ok.py", "add .env.example"). Their files came from a temp folder, so your checkout shows them as deleted.
    - On an unpushed branch: drop them with `git reset --soft <last good commit>`, then recommit.
    - If you already pushed them: don't force-push a shared branch. Commit the deletions, or open a fresh branch from the clean state, as #124 did for #120.
